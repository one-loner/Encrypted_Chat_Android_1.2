# Encrypted Chat — Android-клиент

Нативный проект для Android Studio, Java, Android 7.0 и новее (**minSdk 24**).
compileSdk/targetSdk — 35. Приложение работает с основным режимом
[index.php + web.html](https://github.com/one-loner/encrypted-web_chat_v1.2)
репозитория one-loner/encrypted-web_chat_v1.2, проверенным на коммите
`63c5cce3abfae81ebd42a9e46df8695fba0ef087`.

## Возможности

- Пароль входа в приложение, установка при первом запуске, изменение в настройках.
- Зашифрованное хранение серверного адреса, логина, пароля, ключей и истории.
- Генерация секретов, именование, переименование и удаление неиспользуемых ключей.
- Ввод существующей ключевой фразы для совместимости с веб-клиентом.
- Показ QR, сохранение QR в PNG, импорт QR камерой или вставкой JSON.
- Несколько открытых чатов: горизонтальные свайпы и кнопки названий.
- Отдельные PHP-сеансы каждого чата, опрос раз в две секунды, повторное подключение.
- Отправка текста и зашифрованных вложений до 5 МиБ, сохранение полученных вложений.
- Русский и английский интерфейс, выбор языка в настройках или язык системы.
- Экспорт всей локальной учётной записи в зашифрованный JSON и восстановление.
- Сохранённая история доступна без сети после разблокировки.

## Открытие и сборка

1. Распакуйте проект и откройте папку `EncryptedChatAndroid` в Android Studio.
2. Выберите Gradle JDK **17**. Установите Android SDK Platform 35 и Build Tools 35.0.0.
3. Дождитесь Gradle Sync. Подключите устройство Android 7.0+ или запустите эмулятор.
4. Нажмите Run. SDK 24 — минимальная версия устройства; SDK 35 нужен для компиляции.

CLI (при настроенных `JAVA_HOME` и `ANDROID_HOME`, либо `local.properties`):

```sh
./gradlew assembleDebug
./gradlew testDebugUnitTest lintDebug
./gradlew connectedDebugAndroidTest
```

Windows: используйте `gradlew.bat`.
APK создаётся в `app/build/outputs/apk/debug/app-debug.apk`.
Поставляемый `EncryptedChat-debug.apk` предназначен для установки и проверки;
для распространения соберите release через **Build → Generate Signed Bundle / APK**
со своим signing key. Закрытый signing key в проект не включён.

## Первое подключение

1. Задайте пароль приложения от 12 символов. Он отличается от пароля сервера.
2. В **Настройки → Учётная запись сервера** введите HTTPS-адрес, логин и пароль.
   Например: `https://chat.example.org/ec8/` или
   `https://chat.example.org/ec8/index.php`. Сохраняйте реальный адрес своего сервера.
   HTTPS должен иметь сертификат, которому доверяет Android.
3. Учётную запись предварительно создаёт администратор сервера. Самостоятельная
   регистрация через этот серверный API не предусмотрена.
4. В **Ключи → Новый ключ** задайте имя. Оставьте поле фразы пустым для генерации
   случайного секрета или введите существующую фразу (от 12 символов).
5. В **Чаты → Добавить чат** укажите точное имя комнаты и выберите ключ.
6. Для подключения другого участника передайте ключ через QR и отдельно точное
   название комнаты. Названия чувствительны к регистру.

На сервере требуется актуальный `index.php` из указанного коммита.
Клиент использует `login`, `join_room`, `messages`, `file` и `X-CSRF-Token`.
Изменения сервера для нескольких чатов не нужны: у каждого чата свой CookieJar.
При отзыве сессии приложение прекращает автоматическое подключение к этому чату
и предлагает кнопку **Подключиться снова**. История этого чата временно скрывается.

Гостевой режим `guest.php` и старый интерфейс `app.js` с сырыми Base64 AES-ключами
не входят в этот клиент. Поддерживается текущая веб-версия `web.html`.

## Ключи и совместимость шифрования

Генератор получает 32 случайных байта через SecureRandom и преобразует их в Base64
**ключевую фразу**. Для конкретной комнаты из фразы выводится AES-256-ключ:

```text
chatId = lowercaseHex(SHA-256(UTF-8(chatName)))
salt = UTF-8("encrypted-chat-v1:" + chatId)
key = PBKDF2-HMAC-SHA256(UTF-8(phrase), salt, 600000, 32 bytes)
message = AES-256-GCM(key, random 12-byte IV, UTF-8(JSON payload), 128-bit tag)
```

Тег GCM дописывается к ciphertext, как в WebCrypto. Текстовый payload:
`{"kind":"text","text":"..."}`. Вложения используют поля `kind`, `name`,
`mime`, `data` (Base64), `text` согласно `web.html`.

Для входа через веб-клиент нажмите **Показать фразу** и введите эту фразу в
`web.html`, сохранив такое же название комнаты. Один именованный секрет можно
назначить нескольким чатам: итоговые AES-ключи у разных названий различаются.
Сменить ключ существующего локального чата можно, удалив локальный чат и добавив
его с тем же названием и другим ключом. Старые сообщения под новым ключом не
расшифруются; ключи нельзя удалять, пока они назначены сохранённым чатам.

QR-формат приложения:

```json
{
  "format": "encrypted-chat-key",
  "version": 1,
  "type": "phrase",
  "name": "Имя ключа",
  "phrase": "Секретная ключевая фраза"
}
```

QR содержит секрет в открытом виде. Передавайте QR/PNG только нужным участникам.
Учётные данные сервера в QR не включаются. Системный буфер обмена не используется.

## Защита локальных данных

Хранилище — файл `noBackupFilesDir/vault.enc`, записываемый через AtomicFile:

1. Случайный 256-битный мастер-ключ шифрует JSON учётной записи через AES-GCM.
2. PBKDF2-SHA256 (600000 итераций, случайная 32-байтная соль) из пароля приложения
   выводит ключ, который шифрует мастер-ключ через AES-GCM.
3. Весь контейнер дополнительно шифруется AES-GCM ключом Android Keystore.

На диске нет открытых паролей, фраз и сообщений. В истории сохраняются серверные
шифротексты, расшифровка выполняется в памяти. Фоновая блокировка закрывает диалоги,
очищает расшифрованные сообщения и ключи и отменяет сетевые запросы. После возврата
нужно снова ввести пароль. Камера QR и системный выбор файла получают исключение
до 60 секунд; затем хранилище блокируется. Секретные экраны защищены FLAG_SECURE.

Автоматические облачные копии/перенос данных отключены. Язык хранится отдельно как
несекретная настройка. PHP cookies и CSRF-токены остаются только в памяти.
Java не гарантирует обнуление неизменяемых строк в памяти; приложение не обещает
защиты на взломанном устройстве. Защита Keystore зависит от возможностей устройства.

## Экспорт и восстановление

**Настройки → Экспорт**: задайте и повторите пароль копии от 12 символов,
выберите файл через системный диалог. Пароль копии независим от пароля приложения.
Экспорт включает:

- серверный адрес, логин и серверный пароль;
- все именованные ключевые фразы;
- все локально сохранённые чаты и назначенные ключи;
- загруженные сообщения и шифротексты вложений.

Это снимок локальных данных на момент экспорта. Приложение не скачивает отдельно
всю ещё не загруженную серверную историю при экспорте. После успешного опроса чат
содержит все сообщения, доступные через API сервера. Максимальный файл копии —
100 МиБ. Незашифрованный промежуточный файл не создаётся.

Контейнер: `format=encrypted-chat-account`, `version=1`,
`kdf=PBKDF2-HMAC-SHA256`, `iterations=600000`, `cipher=AES-256-GCM`,
`salt`, `iv`, `ciphertext` в Base64. Соль — 32 байта, IV — 12 байт, тег — 128 бит.

На новом устройстве сначала установите пароль приложения, затем выберите
**Восстановить учётную запись**, введите пароль копии и выберите JSON.
Восстановление полностью заменяет локальные данные после успешной проверки
контейнера. Текущий пароль приложения сохраняется; устройства могут использовать
разные локальные пароли. Cookie-сеансы создаются заново. Неверный пароль,
повреждённая копия или неподдерживаемый формат не заменяют существующие данные.

Если пароль приложения утерян, восстановление локального хранилища невозможно.
Сохраните отдельную зашифрованную копию и её пароль. Удаление приложения уничтожает
локальное хранилище; без копии потерянные ключи восстановить нельзя.

## Проверки

JVM-тесты проверяют опубликованный вектор PBKDF2-SHA256, AES-256-GCM,
независимый Python-вектор для Unicode-фразы/комнаты, экспорт/импорт, отказ при
изменении ciphertext/неверном пароле, ограничения KDF, раздельные cookies/CSRF,
кэширование file-envelope, обработку HTTP 401 и нормализацию HTTPS URL.

`VaultDeviceTest` проверяет реальный Android Keystore, блокировку, отсутствие
секретов на диске, смену пароля, атомарное отклонение некорректного восстановления
и восстановление копии с другим локальным паролем. Файлы тестов изолированы от
пользовательского хранилища. Запуск: `./gradlew connectedDebugAndroidTest`.

Подробные результаты поставляемой сборки см. в `VALIDATION.md`.

Для приёмки на вашем сервере: войдите Android- и веб-клиентами в одинаковую комнату
с одинаковой фразой, обменяйтесь текстом/вложением, добавьте второй чат, проверьте
свайпы и разделение сообщений, QR на втором устройстве, экспорт и восстановление,
отзыв сессий через admin.php, фоновую блокировку и запуск на устройстве API 24.

## Основные файлы

- `MainActivity.java` — интерфейс, языки, чаты, QR, SAF, блокировка и опрос.
- `ChatApi.java` — HTTPS, PHP-сеансы, CSRF и серверные шифротексты.
- `Crypto.java` — WebCrypto-совместимое шифрование и переносимые резервные копии.
- `Vault.java` — пароль, Keystore, атомарное локальное хранилище.
- `res/values*/strings.xml` — локализация; расширяется стандартными Android-ресурсами.

Используются AndroidX ViewPager, OkHttp/Okio, ZXing Android Embedded. Исходники
сервера изучены для совместимости, но не включены в этот проект.
